# Android Play OTA profile

The owner explicitly requested restoring automatic OTA updates for DRASC installed
from the existing internal Google Play track. The application candidate is
`68973cfaa286a80275f7922cb6f0ff3208fed04e`, version 0.1.69, Android code 16.
Its pinned Play runtime is
`5d7bd6ac5d835ea16dd8af8bdea83b645386460b1a2e3d758c1442298ed4d879`.
The existing verification public key is unchanged.

The publisher now accepts an explicit `platforms: ["android"]` approval. Omitting
`platforms` preserves the existing two-platform approval contract. Every selected
platform still requires exact ZIP, source, commit, runtime and previous-channel
hashes. Signing runs only on `release-control`, after the same protected
`production-signing` environment review. No secret, permission or branch guard is
added or removed.

The new Play channel does not exist yet. Bootstrap is permitted only for the
single runtime explicitly pinned in `installed-app.json`, only when the channel
is absent, and only with an approved previous checksum of 64 zeros. An existing
channel still requires a valid signature and its exact previous checksum; the
bootstrap path cannot overwrite it. Native executable payloads are refused before
signing. Old channels remain available and are not deleted or redirected.

The iPhone runtime and channel remain unchanged. Future Play web bundles are
prepared without secrets in the application repository using
`npm run ota:bundle:play`; its frozen native profile rejects native changes.
They are signed and published exclusively here. No application code is imported
or executed by the publisher.

Validation: 16 publisher tests pass, including Android-only selection, absent-channel
bootstrap, refusal to bypass existing signatures/checksums, native executable
rejection and the previous ZIP/signature checks. The exact Android native build
must also pass and match this runtime before this profile is activated.
